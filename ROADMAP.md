# PRAKTIKA — план доработки

Статус: план развития; выполненные пункты отмечены галочками. Жёстких сроков нет. Каждый пункт можно выполнять и принимать отдельно.

## Текущее состояние

- Основной сайт GitHub Pages: https://praporar-web.github.io/praktika-cyberlab/.
- Предыдущая версия опубликована в Sites: https://karnet-practice-lab.modestgiant.chatgpt.site.
- Три трека: Python, C++ и HTML; по 100 заданий и 10 тематических модулей.
- Есть выбор доступного времени, рекомендация следующего блока, черновики, подсказки, каталог, фильтры, ручное подтверждение навыков, экспорт и импорт.
- Прогресс и черновики хранятся в IndexedDB; небольшие настройки — в localStorage. Есть миграция v1 → v2, 5 последних резервных копий и защита от конфликтов вкладок. Между устройствами автоматически не синхронизируется.
- Python и C++ запускаются пользователем локально. Приложение сравнивает вставленный вывод, а не выполняет и не анализирует программу.
- HTML проверяется по структуре DOM и показывается в изолированном предпросмотре.
- Исходные 18 идентификаторов заданий сохранены. Проверена совместимость прежних отметок и черновиков.

- [ ] Новое поведение проверено тестами, соответствующими изменению.
- [ ] Основной сценарий проверен в браузере; изменение интерфейса проверено на мобильной ширине.
- [ ] Изменение имеет понятное описание и может быть отменено возвратом версии.
- [ ] Соответствующий пункт плана отмечен после проверки результата.

## Порядок работы

GitHub Pages уже опубликован, план закреплён в Issue #1. Перенос личного прогресса остаётся отдельным шагом пользователя. Надёжность хранения доработана в v2.1. Следующий этап — настоящая проверка решений и аудит каталога. Удобство коротких сессий дорабатывается небольшими независимыми изменениями. Облачная синхронизация и новые треки — отдельные решения после стабилизации основы.

## Важное при переносе

GitHub Pages публикует страницу в интернете. На GitHub Free исходный репозиторий для Pages должен быть открытым. Существующий закрытый сайт в Sites сам по себе не становится публичным от подготовки этих файлов: публикация на новом адресе — отдельный шаг.

Хранилище браузера привязано к адресу сайта. Прогресс со старого домена Sites на домен github.io автоматически не перейдёт. Нужны экспорт и импорт. После переноса две страницы хранят прогресс независимо.
